Data Processing Workflow

The processes through which the input data goes through are strictly defined in a vertical pipeline. Each stage validates and enriches the data before passing it downstream.

1
Data Ingestion task1/ingest_pipeline

Connects to external systems (data warehouses, APIs, document stores) to securely pull raw business data. It normalizes distinct formats into a standard schema (Time, Region, Product, Metric, Value) required by the analytics engine.

2
Validation & Cleansing task1/normalize.py

Performs rigorous data quality checks. Handles missing values through interpolation, drops corrupted records, and verifies structural integrity. This ensures that upstream data quality issues do not trigger false alerts.

3
KPI Engine & Anomaly Detection task3/anomaly_gate.py

Applies robust statistical modeling (such as trailing baselines, Prophet forecasts, and Z-score gating). It actively scans the time-series data to flag outliers, structural breaks, and early-warning trend shifts.

4
Evidence Retrieval & Causal Analysis task4 & task5

When an anomaly is detected, this layer searches for correlations against internal metrics (e.g. price drops affecting revenue) and external unstructured data (news, event logs). It establishes causality to filter out pure coincidences.

5
LLM Synthesizer task6/synthesize.py

Packages the statistical and causal evidence into a prompt for the selected Large Language Model (e.g., Llama, Gemini, OpenAI). The LLM reasons over the data, formulates root-cause hypotheses, calculates confidence scores, and adapts its narrative for different user personas.

6
Dashboard Rendering app.py

The finalized insights are delivered via REST API to this secure, interactive Business Intelligence dashboard. End users can explore trends, drill down into root causes, and monitor system health.

    Terminology Reference

    A detailed explanation of the parameters used to configure your metrics.

    # Metric Code

    A unique, machine-readable identifier (e.g., ebitda_margin). Used internally by the backend and database to store and query the time-series data. It should contain no spaces or special characters.

    T Display Name

    The human-readable label shown on the dashboard cards, charts, and AI-generated stories (e.g., "EBITDA Margin"). This can contain spaces and capitalization to make reports easy to read for executives and analysts.

    ? Formula

    A mathematical expression used to calculate a derived metric dynamically. You can use basic math (+, -, *, /) combined with existing Metric Codes. If left blank, the system assumes the metric is ingested directly from the data warehouse.

    ? Warning Threshold (%)

    The sensitivity level for early warnings. If the real-time value deviates from the Prophet forecasted baseline by this percentage, the metric enters a Warning state, allowing early intervention before it becomes critical.

    ?? Critical Threshold (%)

    The severity limit that triggers a hard anomaly alert. Breaching this threshold actively fires the LLM synthesizer to perform root-cause analysis, generate hypotheses, and pull contextual news evidence.
